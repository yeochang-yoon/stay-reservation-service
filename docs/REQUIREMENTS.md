# MVP 요구사항 — 정책 검수 초안

작성일: 2026-10-19 (Asia/Seoul)

상태: **Phase 2 / MVP 요구사항 정의 진행 중**. [Kickoff](KICKOFF.md)의 서비스 범위는 사용자 승인으로 확정됐다. 이 문서의 세부 Business Rule·수치·상태 전이·수용 기준은 검수 초안이며 아직 확정하지 않았다. 정책 검수·필수 값 확정·설계 준비 조건을 충족하기 전 요구사항 완료로 처리하지 않는다.

## 1. 승인된 범위와 이번 문서의 경계

포함·제외 범위와 이유는 [Kickoff](KICKOFF.md)가 원본이다. 여기서는 그 범위의 업무 규칙·입출력·실패·검증 기준을 구체화한다. POL-01~06·08·10~11의 추천 방향에 대한 동의는 받았으나 아래 수치·예외·전이를 최종 승인한 것은 아니다.

PG 사업자·결제수단·연동 계약은 PG-GATE에서 실제 지원·접근 조건을 확인한 뒤 설계 단계에서 선택한다. 업무상 요구를 특정 PG가 이미 지원한다고 해석하지 않는다. DB·ERD·API·트랜잭션·락·배치 구조는 이번 문서에서 선택하지 않는다.

## 2. 용어와 범위에서 직접 도출되는 필수 조건

- 객실 타입: 한 숙소 안에서 동일 조건의 객실들을 수량으로 판매하는 단위. 한 타입 안의 객실들은 교환 가능한 공급으로 취급한다.
- 날짜별 공급량: 그 날짜에 이 서비스에 배정한 해당 타입의 판매 한도. 실제 전체 객실 수와 다른 채널의 판매 수량을 혼동하지 않는다.
- 선점: 결제 대기를 위해 한시적으로 확보한 공급. 확정으로 전환할 때 같은 수량을 두 번 차감하지 않는다.
- 예약 가능 여부: 숙소·타입의 판매 상태, 각 숙박일 재고, 정원, 적용 가격과 요청 조건을 함께 충족하는지 판단한 결과.
- 견적: 선택한 날짜·인원에 대한 가격 내역과 취소 조건. 견적 조회 자체는 재고 확보나 예약 확정이 아니다.
- 예약·결제·이용 상태: 서로 다른 업무 사실이다. 결제 화면 이동 성공이나 예정 퇴실일 경과만으로 예약 확정·이용 완료를 판단하지 않는다.
- 계약 내용: 예약 당시 확정한 숙소·타입 표시 정보, 날짜·인원, 박별 금액·총액, 적용 취소 조건과 변경 이력. 이후 상품 변경으로 덮어쓰지 않는다.

핵심 불변 조건은 다음과 같다. 저장 구조나 락 구현 방식의 확정은 아니다.

| ID | 반드시 지킬 결과 |
| --- | --- |
| INV-01 | 각 숙박일의 유효 선점(POL-05의 결과 확인 보호 포함)과 확정 예약이 공급 한도를 넘거나 잔여량을 음수로 만들지 않음 |
| INV-02 | 한 예약의 전체 숙박일 재고가 확보되거나 전혀 확보되지 않음. 일부 날짜만 남는 실패는 허용하지 않음 |
| INV-03 | 같은 업무 요청의 재시도·중복 통지가 예약 확정·수량 전환/복원·환불을 중복 수행하지 않음 |
| INV-04 | 가격·공급·판매 상태 변경이 이미 성립한 계약과 확보 수량을 조용히 훼손하지 않음 |

| INV-06 | 예약 취소와 환불 완료를 구분하고, 실패·미해결 상태와 재처리 근거를 남김 |
| INV-07 | 본인·담당 숙소·서비스 관리자 권한을 모든 변경 경로에서 확인함 |

<a id="pol-01"></a>
### 날짜·시간·판매 기간 (POL-01)

추천 후보: Asia/Seoul의 달력 날짜, 체크인 포함·체크아웃 제외, 1~30박, 체크인 날짜는 오늘부터 180일 이내. 요청한 모든 밤의 공급·요금이 준비돼 있어야 한다. 180일 한도는 체크인 날짜 기준이며 종료일도 데이터가 준비돼야 한다.

숙소별 기본 체크인 15:00, 체크아웃 11:00, 입실 마감 22:00을 후보로 둔다. 관리자는 실제 숙소 시각을 고지·설정하되 이미 확정된 예약의 시각을 변경하지 못한다. 당일 새 선점은 입실 마감 전에만 허용하며 결제 최종 확인 기한도 그 마감을 넘기지 않는다.

대안은 당일 예약 제외 또는 더 긴 판매 기간이다. 전자는 운영이 단순하지만 당일 수요를 잃고, 후자는 장기 공급·요금 준비 부담이 늘어난다. 기본 시각·한도는 최종 검수 대상이다.

<a id="pol-02"></a>
### 인원·예약자 (POL-02)

추천 후보: 예약자는 로그인 회원이자 대표 투숙객. 모든 투숙객을 정원에 포함하고 기준 인원 초과분은 같은 인원 추가 요금을 적용한다. 연령별 할인·침구 상품은 후속 범위다. 1<=기준 인원<=최대 정원<=20명, 총 인원 1 이상·타입 최대 정원 이하를 초기 입력 상한으로 제안한다.

회원의 이메일·비밀번호·표시 이름과 예약 이행에 필요한 대표 투숙객 이름·연락처만 수집하는 안이다. 동행인의 이름·생년월일·신분증·주민등록번호·카드 원문은 수집하지 않는다. 초기 자격 후보는 **만 19세 이상 대표자의 본인 예약·동반 가족 투숙**이다. 자격 자기 확인·약관 버전을 기록하고 입실 때 숙소가 대표자를 확인한다. 생년월일/신분증 업로드나 외부 실명 인증은 도입하지 않으며 자기 확인을 연령 검증 완료라고 표시하지 않는다. 가족 동반은 허용하되 미성년자 단독 예약은 받지 않는 서비스 선택안이며 법적 의무라고 단정하지 않는다. 숙소별 입실 제한을 판매 전에 고지하고 계약 시 보존한다.

타인 명의 예약·연령별 요금은 편의가 늘지만 대표자·동의·수집·입실 검증이 추가된다. 정원 20명은 법적 기준이 아닌 입력 후보이며 더 큰 타입은 범위 재검토 대상으로 둔다.

<a id="pol-03"></a>
### 공급 변경 (POL-03)

공급 감소는 유효 선점(승인 결과 확인 중인 보호 기간 포함)과 확정 예약 수량 이상에서만 가능하다. 판매 중지는 신규 선점을 막되 기존 유효 선점의 완료를 허용하는 안이다. 즉시 이행 불가능한 경우에는 POL-11의 사업자 취소로 처리한다.

기간 일괄 관리 변경은 전체 성공 또는 전체 거절하고, 충돌 날짜와 이유를 반환한다. 실패한 기간 변경으로 일부 날짜만 바뀌지 않는다. 대안인 부분 적용은 운영 편의가 있지만 결과 확인·재시도의 복잡도가 증가한다.

<a id="pol-04"></a>
### 가격·견적·계약 (POL-04)

예약 생성 시 현재 조건을 재검증하고 증가·감소 모두 변경됐으면 재동의를 받는다. 유효 선점 이후에는 가격·입퇴실 시각·취소 정책을 최종 결제 확인 기한까지 고정하고 확정 뒤에도 보존한다. 조회 견적은 공급 확보나 가격 보장이 아니다.

서비스 업무상 계약 성립 후보는 **결제가 검증돼 예약 확정이 성립한 시점**이다. 선점은 조건을 임시 고정한 결제 대기이며 계약일·무료 취소 기산점을 선점 생성일로 조용히 대체하지 않는다. 확정 시 계약 내용과 수령 가능한 확인서를 제공하고 제공/수령 근거를 남긴다. 실제 약관·계약정보 제공 방식과 법적 성립 시점의 정합성은 운영 전에 확인한다. 미확정 대기 취소에는 예약 취소 수수료를 부과하지 않으며 뒤늦은 결제 확인은 POL-06으로 처리한다.

박별 가격은 객실 숙박료+max(0, 총 인원-기준 인원)×해당 날짜의 1인 추가 요금으로 계산하고 전체 밤을 합산한다. 첫 버전은 표시 요금에 세금/필수 비용을 포함하고 결제 직전 필수 요금을 추가하지 않는 안이다. 후보 상한은 박당 객실 숙박료 1~10,000,000원, 추가 인원 1인·1박 0~1,000,000원이며 원 단위 정수로 입력한다. 실제 PG 결제 가능 금액 범위에 맞지 않는 상품은 판매하지 않으며 그 범위는 PG-GATE에서 확인한다. 원 미만이 생기는 공제액은 버림해 고객에게 불리한 초과 공제를 막는 안이다.

확정 뒤 날짜·타입·인원 변경은 취소·재예약으로 처리한다. 취소 비용·새 예약 실패 위험을 미리 안내하고 원예약을 자동 복원하지 않는다. 대안은 기존 예약 재견적으로서 새 재고 확보·차액·변경 이력의 추가 설계가 필요하다.

<a id="pol-05"></a>
### 선점·PG 처리 중 만료 (POL-05)

**추천 후보: 고객 결제 시도 10분 + 기한 안에 접수된 승인 시도에만 최대 2분의 결과 확인 보호 기간**. 무조건 12분을 제공하는 것은 아니다. 각 기한을 고객에게 보여주고, PG의 상태·시간 제한을 서비스 기한과 동일하다고 가정하지 않는다.

- 선점 생성 시각을 T0, 예약에 고지한 입실 마감을 C로 두고 새 승인 시도 마감을 T1=min(T0+10분, C), 최종 보호 한도를 T2=min(T1+2분, C)로 둔다. 새로고침·중복 요청·재시도는 연장하지 않는다.
- 서비스가 T1 전에 승인 시도를 접수해 처리 중/결과 불명인 경우만 T2까지 공급을 유지한다. 승인 시도가 없으면 T1에 만료한다. 명확한 결제 실패는 T1 전 동일 예약으로 새 결제 의도를 시작할 수 있으나 중복 청구 위험이 없음을 확인해야 하며 기한을 연장하지 않는다. 고객의 대기 취소는 즉시 종료하고, T1에 진행 중 시도가 없으면 T2 보호를 부여하지 않는다.
- T1 이후 새 승인 시도는 거절한다. 같은 승인 시도의 재확인·조회·동일 의도 재시도만 허용하며 새 결제 건을 만들지 않는다.
- 입실 마감으로 단축되면 고객에게 기한을 알린다. C가 이미 지났으면 선점하지 않는다. 실제 PG의 최소 처리/만료 제약으로 남은 시간에 처리할 수 없는 경우에도 새 승인 시도를 받지 않는 조건을 PG-GATE에서 검증한다.
- 공급을 유지한 상태에서 서비스가 기한 안에 검증한 성공은 확정할 수 있다. T2에 결과가 여전히 불명확하면 만료·공급 반환과 결제 조사 상태를 구분한다.
- 계정별 동시 유효 대기 후보 한도는 3건이다. 동일 의도는 같은 건으로 계산하고 이미 종료된 건은 제외한다. 계정/접속 남용 제한의 기술은 설계에서 정한다.

비교 예시: PG가 9분 59초에 성공했으나 응답이 10분 1초에 왔다면, 선점 유지·검증·보호 기간 조건을 충족할 때 확정한다. PG가 10분 30초에 성공한 경우도 원래 승인 시도가 T1 전 접수되고 T2 전 검증되면 처리 가능하다는 안이다. 반대로 9분에 성공했더라도 12분 경과·만료 후에야 확인되면 승인 시각만으로 공급을 되살리지 않는다.

PG가 신뢰 가능한 승인 시각을 제공하지 않을 수도 있으므로 그 필드를 필수 제공한다고 가정하지 않는다. 서비스의 접수·수신·검증·상태 전이 시각과 실제 확보 상태를 근거로 판단하며, 만료와 확정은 하나의 결과만 갖도록 해야 한다. 기한 정각은 새 처리 불가(시간 < 기한만 유효)를 후보로 둔다.

대안은 10분 즉시 만료(명확하지만 정상 결제 환불 증가) 또는 확인될 때까지 무제한 보호(공급 잠금·장애 전파)다. 2분과 3건은 승인되지 않은 후보이며 실제 PG 처리·조회 조건을 확인한 뒤 설계에서 재검증한다. 지원 조건상 불가능하면 사용자와 정책을 다시 검토한다.

<a id="pol-06"></a>
### 불확실·늦은 결제 (POL-06)

브라우저 성공 화면·타임아웃·검증하지 않은 알림만으로 결제를 확정하지 않는다. 성공/실패가 불확실하면 조사 상태를 표시하고 가능한 PG 조회·대조로 판정한다. 고객에게 중복 결제를 재촉하지 않는다.

T2 뒤, 이미 취소/만료·공급 반환 뒤에 검증된 성공이 확인되면 자동 부활하지 않는다. 취소/환불 또는 운영 조치로 수렴하며 선점 만료와 금전 미해결을 별도 기록한다. 원래 승인 시각이 이르다는 이유로 다른 고객에게 판매된 공급을 빼앗지 않는다.

후속 조회·재처리 후보는 최초 1분 간격, 연속 5회 확인 실패 시 운영 확인 대기에도 올린다. 이후에는 운영자가 인수하거나 권위 있는 결과를 얻을 때까지 저빈도 자동 대조를 지속하는 안이며, 정확한 호출 제한·백오프·종료/인수 조건은 PG 지원 조건과 함께 설계에서 정한다. 복구 완료 목표 후보는 정상 재처리 가능 시 10분, 외부 장애 지속 시 1영업일 내 운영 확인이다. 이는 현재 측정된 성능이나 환불 법정 기한의 대체가 아니다.

대안인 늦은 성공 부활은 결제 편의가 있지만 종료 상태·새 재고·새 가격과 충돌한다.

1. 아직 실제 이용이 개시되지 않은 계약 체결 당일의 요청은 무료 취소를 제공하는 안이다. 분쟁 기준의 당일 표현과 별개로 우리 서비스가 제공할 고객 우대 조건이다.
2. 체크인 날짜가 아직 도래하지 않았고 계약정보 수령일의 다음 날부터 7번째 KST 달력일 종료까지의 요청에는 고객 우대 무료 취소를 제공하는 안이다. 계약정보 수령 지연/누락도 기록하며 뒤늦게 수령한 고객에게 계약일만으로 기한을 줄이지 않는다. 이 서비스 혜택과 법정 철회의 기산점·제한·고지 요건은 구분한다. 한국소비자원은 2026년 안내에서 미도래 숙박의 7일 이내 철회를 다뤘고, 현행법에는 공급·정보 수령·가치 감소·용역 개시 등 조건이 있다. 분명하지 않은 권리 주장은 운영 검토로 접수한다. [2026 소비자원 안내](https://www.kca.go.kr/home/sub.do?menukey=4005&mode=view&no=1004481539&page=1&searchKeyword=환불), [전자상거래법 제17조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029561577).
3. 사업자 이행 불가, 표시와 다른 상품, 기후·자연재해로 이용/이동 불가, 법정 면제·감면 가능 사유는 일반 수수료를 자동 확정하지 않고 근거·요청 시각을 남겨 서비스 관리자가 검토한다. 2025 개정은 이동 경로 일부의 기후·자연재해도 명시했다. 개인 사정·개별 질병을 무조건 같은 예외로 취급하지 않는다. [2025 개정 근거](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000270136&chrClsCd=010202&urlMode=admRulRvsInfoR).
4. 계약·가격·취소 조건과 고객의 유효 요청 접수 시각을 보존한다. 운영자의 처리 지연으로 더 비싼 날짜 구간을 적용하지 않는다. 금액이 달라졌다면 재동의를 받고, 외부 응답 재시도로 접수 기준을 바꾸지 않는다.
5. 유효한 철회/전액 환급 사유를 수수료표나 환불 불가 문구로 차단하지 않는다. 전자상거래법 제17조에 따른 철회에 제18조가 적용되는 경우, 용역/미공급 거래의 환급은 철회한 날부터 3영업일 이내이며 결제수단의 청구 정지/취소 요청도 지체 없이 해야 한다. 서비스 목표 후보는 유효 취소 수락 직후 PG 요청, 미해결 건 매일 확인이다. PG 요청 성공과 고객 환급 완료는 구분하고 지연·미확정은 운영 조치로 남긴다. 단순 PG 요청만으로 법정 환급 의무 전체를 이행했다고 단정하지 않는다. [제18조의 기한·결제수단별 의무](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1027063343).

**대안 B**는 공식 4개 분류표를 기본 정책으로 채택해 성수기·주말·다박 분류·계약일·예외를 모두 구체화하는 것이다. 공급자 손실 반영은 크지만 조건과 검증 조합이 늘어난다. **A를 추천하되 공급자는 이 공통 정책에 동의해 판매해야 한다.** A/B, 무료 우선 규칙, 다박·접수 기준을 사용자 검수 후 확정한다.

<a id="pol-08"></a>
### 취소 수락·재고·환불 (POL-08)

허용된 취소를 수락하면 예약을 종료하고 **미사용이며 해당 날짜 입실 마감 전인 밤**의 공급만 한 번 반환한다. 오늘 밤도 미사용·판매 기한 안이면 반환 대상이며, 이미 지난 밤·사용한 밤·판매 기한 종료 날짜를 새 공급처럼 복원하지 않는다. 환불은 별도 추적하고 실패해도 예약을 부활시키지 않는다. 이후 문서의 ‘재판매 가능한 미래 공급’도 이 정의를 따른다.

수수료 견적 조회는 취소 수락이 아니다. 유효 취소 의사가 접수된 시각·그때 동의한 조건을 남기고, 중복/재시도는 같은 결론을 따른다. 전날 조회만 하고 당일 처음 제출했다면 당일 새 견적/동의가 필요하다. 전날 유효하게 제출했으나 내부 처리/PG 응답만 당일로 밀렸다면 전날 접수 기준을 유지한다. 내용 변경이면 새 동의를 요구하되 기존 유효 의사를 삭제하지 않는다. 법정 권리 주장은 운영 접수 경로로도 받으며 발송 시 효력이 발생하는 서면 철회 등은 법정 유효 시점의 근거를 따로 보존해 판단한다.

대안인 PG 환불 완료 후 재고 반환은 금전 처리는 보수적이지만 장애 중 취소·재판매가 막힌다. PG 부분 취소·환불을 지원한다고 가정하지 않으며, 수수료·조기퇴실을 처리할 실제 기능을 선정 전에 확인한다.

<a id="pol-09"></a>
### 이용·노쇼·조기퇴실·정정 (POL-09)

| 업무 | 추천 후보와 예외 |
| --- | --- |
| 정상 체크인 | 확정 예약·담당 관리자·실제 도착 확인. 예약에 보존한 체크인 시각부터 합의한 입실 마감까지. 선입실은 사유를 남기는 예외 승인 업무 |
| 지연 입실 | 고객과 합의한 연장 마감·연락 사실을 기록. 원래 마감만 지났다고 노쇼 처리하지 않음. 연장과 이미 판정한 노쇼는 별도 관리 |
| 노쇼 | 합의된 최종 입실 마감이 지났고 실제 체크인하지 않았음을 담당자가 확인해 제안. 금전/종료 영향을 서비스 관리자가 확인한 뒤 확정. 자동 노쇼·자동 100% 몰수 금지. 비용은 POL-07의 당일 기준과 유효 무료 요청/예외를 검토. 며칠 뒤 처리해도 최초 미도착일의 당일 기준을 바꾸지 않음 |
| 정상 체크아웃 | 실제 체크인 후 실제 퇴실을 담당자가 기록하면 이용 완료. 시간이 지났다는 이유로 자동 완료하지 않음. 예정 퇴실을 넘겼다면 운영 미처리 경고 후보 1시간 후 표시. 지연 퇴실로 자동 연박/추가 청구하지 않으며 다음 예약 이행 위험은 담당자·서비스 관리자에게 전달 |
| 조기퇴실 | 실제 사용한 박의 금액은 보존하고 미사용 박을 구분. **추천: 다음 박 체크인 시각 전에 퇴실하면 그 박 이후 미사용 금액 전액 환급**, 재판매 가능 공급 반환. 정각부터 시작한 박은 사용분이며 해당 박 계약 금액(추가 인원 포함)을 보존. 실제 퇴실 시각을 근거로 하고 직원의 지연 입력으로 사용 박을 늘리지 않음. 특별 사유·품질 불량은 별도 검토 |
| 노쇼·조기퇴실 후 공급 | 종료가 수락된 뒤 재판매 가능한 미사용 미래 날짜만 한 번 반환. 과거·이미 사용한 날짜는 복원하지 않음. 후일 늦게 도착해도 종료 예약으로 입실 보장하지 않음 |
| 정정 | 원 기록을 덮어쓰지 않고 요청자·사유·발생/기록 시각·승인자를 남김. 경미한 시각 정정도 이력 유지. 재고·금액·완료·리뷰 자격에 영향이 있으면 서비스 관리자 승인과 재검증 필요 |
| 종료 예약 복구 | 노쇼/취소 정정으로 예약을 재개하려면 새로 필요한 미래 공급과 계약/환불 상태를 검증. 다른 고객 공급을 빼앗거나 결제를 다시 청구하지 않음. 불가능하면 거절·운영 조치 |

조기퇴실의 부분 환불과 노쇼의 공제는 고객에게 사전에 표시하고 기록한다. 노쇼의 자동 판정/전액 환불 불가나 관리자의 임의 점수 조정은 채택하지 않는다. 대안은 미사용 박에도 취소표 공제를 적용하거나 날짜만으로 완료하는 안이며 각각 공급자 수익/편의와 고객·리뷰 신뢰의 trade-off가 있다.

정정으로 이용 자격이 없어지면 관련 리뷰를 즉시 비공개 처리·집계 제외하고 작성자 이의제기 경로를 안내한다. 복구 가능 여부·증거는 운영자가 검토하며 임의 삭제로 분쟁을 숨기지 않는다.

<a id="pol-10"></a>
### 리뷰·평점 (POL-10)

후보: 실제 1박 이상 이용 완료한 본인 예약당 1개, 1~5점 정수·본문 1~2,000자. 실제 이용 완료 시각부터 30일 이내 작성/수정하며 본인 삭제는 그 이후에도 허용한다. 삭제한 예약의 새 리뷰 재작성은 제한한다. 조기퇴실도 실제 사용분이 있으면 가능하고 노쇼/취소/미확정은 불가하다.

공개·유효 리뷰만 산술 평균/개수에 반영하고 0개는 미평가로 표시한다. 평균 표시는 소수 첫째 자리 반올림을 후보로 둔다. 사용자 수정만으로 관리자 비공개가 해제되지 않는다.

공개 기간 후보는 본인 삭제·탈퇴·정당한 비공개 전까지이며, 비공개 기준·등급 계산·삭제·이의제기 방법을 안내한다. 사업자에게 불리한 점수라는 이유만으로 숨기지 않는다. 후기 처리 정보의 공개는 현행 전자상거래법에도 규정돼 있다. [제21조의4 후기 처리 정보 공개](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1034118709).

대안은 무기한 작성/수정 또는 삭제 뒤 재작성 허용이다. 참여 편의는 늘지만 오래된 경험·평가 남용 관리가 추가된다. 탈퇴 후 처리는 POL-12가 원본이다.

<a id="pol-11"></a>
### 관리자·사업자 취소 (POL-11)

일반 가입으로 관리자 자격을 얻지 못한다. 서비스 관리자가 담당 숙소를 부여/해제하며 해제 즉시 이후 접근을 차단한다. 기존 거래는 새 담당자/서비스 관리자가 이어서 처리한다.

사업자 취소는 담당 관리자가 사유를 요청하고 서비스 관리자가 확인한다. 고객 전액 환불과 추가 보상/대체 제공 검토를 분리한다. 공식 기준에는 사업자 귀책의 환급 외 배상도 있으므로 전액 환불만으로 모든 의무가 끝났다고 처리하지 않는다. 첫 버전은 추가 배상 자동 계산 대신 운영 판단·합의·지급/미해결 이력을 남기는 안이다. [사업자 귀책 공식 참고표](https://www.easylaw.go.kr/CSP/CnpClsMainBtr.laf?ccfNo=4&cciNo=3&cnpClsNo=2&csmSeq=534&popMenu=ov).

대안인 숙소 관리자 즉시 강제 취소는 빠르지만 고객 피해·남용 가능성이 커진다. 계정 공유·임의 상태/금액 수정으로 운영 문제를 해결하지 않는다.

<a id="pol-12"></a>
### 탈퇴·접근 종료·보존·파기 (POL-12)

**추천은 기존의 ‘미해결 거래가 있으면 탈퇴 전체 보류’를 수정해 접근 종료와 거래 이행을 분리하는 안**이다.

- 본인 확인 후 탈퇴를 접수하면 신규 서비스 이용·로그인·기존 세션/토큰을 종료한다. 법적/계약상 필요한 처리와 거래기록 열람·취소/환불 요청은 별도 본인 확인 운영 경로로 계속 제공한다.
- 이 경로의 확인 수단은 설계에서 정하되 예약 번호·이름·검증되지 않은 연락처를 알고 있다는 사실만으로 거래 열람/변경을 허용하지 않는다. 확인할 수 없으면 권한을 우회하지 않고 보완 요청·처리 근거를 남긴다.
- 활성 예약·환불이 있어도 계약을 조용히 취소하거나 처리 근거를 삭제하지 않는다. 계정 접근 종료와 개인정보 처리정지/삭제 요청의 판단을 분리하고 필요한 정보·이유·기간을 고지한다.
- 비밀번호·세션·일반 프로필과 더 이상 필요 없는 연락처 사본은 지체 없이 파기하는 안이다. 작업 목표 후보는 접수 시 접근 즉시 차단, 파기 처리 5일 이내다. 5일은 법정 유예가 아니라 서비스 처리 상한 후보이며 불필요한 정보는 기다리지 않는다.
- 법령에 따른 보존·현재 계약 이행/분쟁 처리가 필요한 최소 정보만 목적별로 제한 보관한다. 일반 서비스/마케팅 재사용 금지, 권한·열람·파기 이력과 종료일을 관리한다.
- 표시 이름 마스킹·해시·계정 연결 해제만으로 익명화됐다고 주장하지 않는다. 재식별 가능한 가명 정보는 개인정보로 관리한다.
- 추천 후보: 탈퇴 시 공개 리뷰를 비공개·집계 제외하고, 불필요한 본문/작성자 식별은 5일 이내 파기한다. 필요한 분쟁 증거는 해당 목적/기간으로 제한한다. 대안은 실질 익명화 후 공개 유지이나 재식별·작성자 권리와 거래 연결 검토가 필요하다.

**공식 근거**: 불필요 개인정보의 지체 없는 파기, 다른 법령 보존 예외와 분리 관리가 개인정보 보호법 제21조에 규정돼 있다. 거래기록은 목적과 기간을 구분하며 보존했다고 일반 계정 이용을 계속 허용하는 것은 아니다. [현행 개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1027063705), [거래기록 보존·열람](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=3&cnpClsNo=2&csmSeq=2985&menuType=cnpcls&popMenu=ov).

법령의 보존 기간과 서비스가 제안한 기산·처리 SLA는 구분한다. 항목별 수집·접근·종료 사건·보존 이유와 기간·삭제 방식을 설계에 인계하며, 아래 수용 기준으로 검증한다.

로그아웃은 현재 세션을 즉시 무효화하고 탈퇴·계정 이용 제한·관리자 권한 해제는 모든 관련 접근을 즉시 차단하는 안이다. 인증 수단/만료 방식과 남용 방어 수치는 보안 설계에서 실제 방식을 검토하되 이 접근 종료 요구를 완화하지 않는다. 유효 선점·계약·취소 동의의 버전/접수 시각은 보존하며, 중복 의도 식별의 보관 기간은 해당 거래의 보존 목적과 함께 POL-12를 따른다.

## 6. 업무 상태 전이 초안

이름은 업무 설명이며 DB Enum·테이블·API 계약이 아니다. 아래 전이와 시점은 POL 정책 검수 후 확정한다.

| 대상 | 정상 전이와 종료 | 허용하지 않는 처리 |
| --- | --- | --- |
| 예약 | 생성·전체 날짜 선점 → 결제 대기 → 유효 공급/기한 안의 검증된 결제로 확정 → 이용 업무 연결. 새 승인 마감/보호 종료는 POL-05. 대기 취소/만료는 종료, 명확한 결제 실패 뒤에는 기한 내 재시도 가능. 확정은 허용된 취소/노쇼로 종료 | 부분 날짜만 선점, 만료/취소 예약 자동 부활, 동일 예약 두 번 확정. 결제 시도 실패만으로 이미 확인된 성공 덮어쓰기 |

| 계정·데이터 | 정상 이용 → 탈퇴 접수·접근 종료 → 목적별 최소 기록 보존/불필요 정보 파기 → 기간 종료 파기. 미해결 계약은 별도 본인 확인 운영 경로로 이행 | 거래가 남았다는 이유로 모든 접근/프로필 유지, 탈퇴를 예약 취소로 처리, 재가입 계정에 과거 거래·관리자 권한 자동 연결, 가명화를 익명화로 보고 무기한 보관 |

## 8. PG-GATE — 설계 전에 확인할 외부 환경

아래는 특정 사업자의 지원 기능을 주장하는 목록이 아니라 **확인·선정 기준**이다.

| 확인 항목 | 확보할 근거와 미지원 시 처리 |
| --- | --- |
| 접근 조건·수단 | 테스트 계정·키·계약 필요 여부, 지원 결제수단, 서버/브라우저 절차, 테스트 데이터와 외부 접속 조건 확인 |
| 승인·조회·취소 | 실제 테스트 환경에서 가능한 작업과 응답/식별자·금액·부분 취소 제약 확인. 첫 버전 업무가 불가능하면 다른 PG 또는 범위를 사용자와 재검토 |
| 알림·정당성 | 해당 결제수단이 어떤 이벤트를 실제 보내는지, 재전송·순서·인증 검증 방법 확인. 없는 웹훅·서명을 가정하지 않으며 지원 조회/대조 등의 대안을 검토 |
| 만료·멱등·불확실 | PG의 시간 제한과 서비스 기한을 구분. POL-05의 기한·입실 마감 단축·늦은 승인 취소가 실제 지원으로 가능한지 확인. 승인 시각 필드의 존재/신뢰도·멱등·일관성 지연·조회 제한도 증거 확보 |
| 실제 검증과 모의 검증 | 실제 PG에서 확인한 정상/실패 결과와 모의로만 재현한 지연·중복·응답 유실을 분리 기록. 라이브 키·실금전 거래는 사용하지 않음 |

미지원 기능을 Mock으로 채운 뒤 PG 연동이 완료됐다고 보고하지 않는다. PG 상태를 서비스 상태와 일대일 대응한다고 미리 가정하지 않는다. 이 단계에서는 PG를 선정하거나 연동 코드를 만들지 않는다.

- POL-01~12의 채택/수정과 날짜·인원·가격·취소·이용·리뷰·보존 정책의 필수 값 확정. 여러 날짜 관리 변경과 예약 수정 방침도 포함.
- 입력 범위/필수 정보, 예상 오류와 사용자 안내, 취소/이용/예외 상태 전이의 충돌 해소.
- 특히 취소 수수료표·노쇼/조기퇴실·탈퇴/보존은 구조 승인만으로 숫자·예외까지 확정하지 않음.
- 각 Business Rule의 정상·실패·시간 경계·권한·동시성 수용 기준과 예상 DB 결과를 검수.
- PG는 기능을 가정하지 않고 PG-GATE의 증거를 설계 단계에서 확보할 작업으로 인계. 그 전 기능별 구현 계약은 확정하지 않음.
- 개발 절차의 요구사항 완료 조건을 충족하는지 확인한다. 이번 세션의 경계·종료 점검은 [AGENTS.md](../AGENTS.md)를 따른다.

현재는 문서 초안 준비와 검수 단계다. 자동화된 링크/범위 검사와 자체 Review는 문서 품질 검증이며 위 기능 Test의 실행 결과를 대신하지 않는다.
