# Project Kickoff

작성일: 2026-10-19 (Asia/Seoul)

상태: **사용자 검수 대기 중인 범위안**. 기존에 확정한 기능·학습 목표를 제외한 아래 추천 범위는 아직 확정하지 않았다.

## 목적과 서비스 성격

사용자가 숙소와 객실을 조회하고 원하는 기간의 객실을 예약·취소하며 이용 경험을 리뷰로 남길 수 있는 숙박 예약 웹서비스를 만든다.

같은 객실에 요청이 동시에 들어와도 중복 예약이 성립하지 않는 것이 핵심이다. 개발·Test·Review·CI·배포·운영·기존 서비스 변경을 연결하고, 설계 근거와 실제 검증 결과를 설명할 수 있는 프로젝트를 목표로 한다.

## 이미 확정된 방향

- Java / Spring / JPA 기반으로 진행한다. 구체 버전·Build Tool·DB 계열은 설계 단계에서 결정한다.
- 회원 인증·인가, 숙소·객실 조회, 예약·취소, 예약 기간 중복 검증, 리뷰·평균 별점이 주요 기능이다.
- 예약 트랜잭션, JPA 비관적 락, 실제 RDBMS 기반 동시 예약 통합 테스트가 핵심 학습 목표다.
- Codex가 실제 개발을 주도하고 사용자가 중요한 결정과 결과를 검수한다. 상세 역할과 안전 원칙은 [AGENTS.md](../AGENTS.md)를 따른다.
- Backend 독립 검증·배포·운영 후 Frontend를 선택·개발하고 최종적으로 전체 웹서비스까지 완성한다.

## 주요 사용자와 핵심 시나리오 — 제안

- 비회원: 숙소와 객실 정보를 조회한다.
- 회원: 로그인 후 객실을 예약하고 본인의 예약을 조회·취소한다. 리뷰를 작성하고 숙소의 리뷰·평균 별점을 조회한다.

기본 흐름은 **숙소·객실 조회 → 회원 가입·로그인 → 날짜 선택·예약 → 본인 예약 확인 → 취소 또는 이용 후 리뷰 → 평균 별점 확인**이다.

실패 흐름도 MVP의 일부로 다룬다. 기간 중복, 유효하지 않은 날짜, 미인증 요청, 타인의 예약 취소, 리뷰 작성 자격 미충족 등을 검증한다. 구체적인 자격과 날짜 정책은 다음 요구사항 단계에서 결정한다.

## 첫 MVP에 포함할 범위 — 추천안

| 영역 | 추천 범위 |
| --- | --- |
| 인증·인가 | 회원 가입·로그인, 보호된 기능의 인증, 본인 데이터 접근 권한 |
| 숙소·객실 | 초기 데이터로 제공한 숙소·객실의 목록·상세 조회. 구체적인 검색 조건은 요구사항 단계에서 정함 |
| 예약 단위 | 객실 한 건은 실제 판매 가능한 실물 객실 1개. 같은 기간에 유효한 예약은 최대 1건 |
| 예약·취소 | 결제 없이 예약 성공 시 즉시 확정. 본인 예약 조회·취소 및 중복 예약 방지 |
| 리뷰·별점 | 예약·이용과 연계한 리뷰 작성, 숙소별 리뷰와 평균 별점 조회. 작성 자격·수정·삭제 정책은 다음 단계에서 확정 |
| 화면 | 위 핵심 흐름을 수행하는 최소 웹 UI. Frontend 기술은 절차에 정해진 시점에 선택 |

## 첫 MVP에서 제외할 범위 — 추천안

- 객실 타입별 여러 개의 재고를 묶어서 판매하는 모델.
- 숙소 운영자 가입, 숙소·객실 등록·수정·삭제용 API와 관리 화면. 초기 데이터 준비 방식은 Backend 기반 구축 때 결정한다.
- 실제 결제·환불·정산, 예약 대기·결제 제한 시간.
- 소셜 로그인, 비밀번호 재설정 메일, 문자·이메일 알림.
- 쿠폰·포인트·즐겨찾기·추천·지도 검색·사용자 파일 업로드.
- 다중 객실 일괄 예약, 외부 숙박 플랫폼 연동.

이들은 첫 MVP의 범위를 명확히 하기 위한 제외안이다. 실제 요구가 생기면 Backlog나 배포 후 변경 후보로 검토한다.

## 지금 확인할 중요한 선택

| 선택 | 추천안과 이유 | 대안과 영향 |
| --- | --- | --- |
| 예약 단위 | 실물 객실 1개. 한 객실의 예약 정합성과 락 동작에 집중할 수 있음 | 객실 타입 + 수량 재고. 재고 차감·복원과 기간별 재고 설계까지 범위가 커짐 |
| 예약 확정 | 결제 없이 즉시 확정. 예약 트랜잭션·취소 흐름을 먼저 검증 | 결제 연계. 임시 예약, 만료, 결제 실패·환불까지 요구사항이 늘어남 |
| 숙소 데이터 관리 | 초기 데이터 제공. 조회·예약·리뷰 흐름을 빠르게 완성 | 운영자 CRUD·관리 화면. 사용자 역할과 관리 기능·검증 범위가 추가됨 |

사용자는 추천안 전체를 채택하거나 변경할 항목만 지정할 수 있다. 이 선택은 도메인과 MVP 크기를 바꾸므로 구현 전에 확인한다.

## 핵심 기술 목표의 검수 근거

구현 단계에서 다음 근거를 제시한다. 이는 향후 검증 목표이며 현재 Test를 실행했다는 뜻은 아니다.

- 예약 과정의 트랜잭션 경계, 중복 검증과 저장의 순서, 실패 시 Rollback 결과.
- 비관적 락의 대상·획득 시점·유지 범위와 선택 이유. 동시 요청에서도 정합성을 보장하는 근거.
- 같은 실물 객실의 충돌하는 기간에 여러 요청을 동시에 보냈을 때 성공·거절 건수와 최종 DB 상태.
- 실제 RDBMS의 독립된 트랜잭션으로 경쟁을 재현하는 통합 테스트 및 반복 실행 결과.
- 비중복 기간·다른 객실의 정상 예약, 취소 후 재예약 등 정상 흐름을 함께 보장하는 테스트.

상세 날짜 경계·중복 판정·취소·리뷰 정책, ERD·API·락 구현은 요구사항과 설계 단계에서 확정한다.

## Kickoff 완료 조건과 다음 단계

서비스 대상·핵심 시나리오·MVP 포함/제외 범위·중요 학습 목표를 사용자가 검수하고 범위를 확정하면 Kickoff를 완료 처리한다. 문서 작성만으로 완료하지 않는다.

확정 후 [개발 절차](DEVELOPMENT_PROCESS.md)에 따라 MVP 요구사항 → 초기 설계 → Backend 기반 구축 순서로 진행한다. 요구사항 단계에서는 역할, 예약 날짜와 취소 규칙, 리뷰 자격, 정상·실패 흐름과 완료 기준을 구체화한다.
